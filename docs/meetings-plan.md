# Встречи (Google Таблица) — план на будущее

> **Статус:** отложено, не реализовано.  
> **Триггер:** **«Давай к встречам»** / **«вернёмся к встречам»**.  
> **Файл плана:** `docs/meetings-plan.md`

## Итоговые требования (согласовано)

- Меню **«Встречи»** → **Результат** | **Новая встреча** | **Календарь встреч**.
- Таблица Google: структура известна, **большая накопленная база** строк.
- **Просмотр:** все встречи всех менеджеров. **Редактирование:** только свои (колонка email = почта входа в PWA).
- Поиск по **телефону** (`79999999999`) или **ID сделки** → список всех совпадений, шапка **«Найдено встреч: N»**; одна встреча = одна строка.
- **Выполнено:** не флаг, а **три заданные ячейки** заполнены.
- **Календарь:** все встречи текущего месяца, группировка по датам, выполнено/нет; чужие — только просмотр.
- **Новая встреча:** новая строка, email менеджера = текущий пользователь.

## Идея

Пункт меню **«Встречи»** → три режима:

| Режим | Действие |
|-------|----------|
| **Результат** | Ввод телефона или ID сделки → показ строки из таблицы (фиксированный набор колонок) → редактирование → **перезапись** в Google Sheets |
| **Новая встреча** | Та же форма, поля пустые → заполнение → **новая строка** в нужные колонки |
| **Календарь встреч** | Список встреч **текущего месяца**, группировка по датам, статус **выполнено / не выполнено** |

## Доступ (просмотр / редактирование)

| Действие | Правило |
|----------|---------|
| **Просмотр** | Менеджер видит **все встречи** (всех менеджеров) — поиск, календарь, списки. |
| **Редактирование** | Сохранять в таблицу можно **только свои** встречи: колонка **email менеджера** = почта из авторизации PWA. |
| **Новая встреча** | Всегда создаётся **от имени текущего** пользователя (email подставляется автоматически). |

**UI для чужой встречи:** форма открывается **только для чтения** (поля неактивны, без кнопки «Сохранить» или с подписью «Редактирование доступно только владельцу встречи»). В списке/календаре можно показывать email или имя ответственного менеджера.

Проверка права на запись — **только на сервере** при `POST`/`PATCH`; клиент не может перезаписать чужую строку.

## Техническая база (как в проекте)

- Тот же **service account** (`GOOGLE_SERVICE_ACCOUNT_JSON`), что для Референса.
- Для записи нужен scope **`spreadsheets`** (не `readonly`) и роль **Редактор** на таблицу встреч.
- Отдельные env: `MEETINGS_SHEET_ID`, `MEETINGS_SHEET_GID` (или имя листа).
- Маппинг колонок — конфиг (JSON / env): какое поле формы → буква колонки или заголовок.

## Данные таблицы

- Структура таблицы **уже зафиксирована**, в таблице **большой накопленный объём** строк — импорт истории не нужен, работаем с живой таблицей.

## Поиск (Результат)

1. Нормализация телефона: **`79999999999`** (как для amo — без `+`, `-`, пробелов).
2. Если введён **ID сделки** — поиск по колонке ID (точное совпадение).
3. **Одна встреча = одна строка**, но по одному телефону (или ID) встреч может быть **несколько**.
4. UI: список **всех** найденных встреч **одна под другой**; в шапке — **«Найдено встреч: N»**; у каждой строки — признак «моя» / менеджер (email).
5. Тап по встрече → форма: **своя** — редактирование и «Сохранить»; **чужая** — только просмотр.
6. Ничего не найдено по телефону/ID → «Не найдено».

## Новая встреча

- `append` строки или запись в первую пустую (лучше **append**).
- Автозаполнение: email менеджера, дата создания (если есть колонки).
- Валидация обязательных полей до отправки.

## Статус «выполнено»

Не отдельная колонка «да/нет», а **три заранее заданные ячейки** (конкретные поля формы / колонки таблицы).

- Встреча считается **выполненной**, если **все три** ячейки заполнены (не пустые).
- Иначе — **не выполнена**.
- В календаре и в списках показываем этот признак по правилу трёх полей.

*(При реализации зафиксировать в конфиге, какие именно три колонки.)*

## Календарь

- Загрузка **всех** встреч за **текущий месяц** (колонка даты встречи) — **без** фильтра «только мои».
- Группировка по дате в UI; в карточке встречи — менеджер (email), статус выполнено/нет.
- Статус выполнено/нет — по правилу **трёх заполненных ячеек**.
- Тап по встрече → форма: своя — редактирование, чужая — просмотр.
- Опционально позже: фильтр «только мои» в календаре (не в MVP, если не попросят).

## UI (черновик маршрутов)

```
/menu → Встречи (/meetings)
  ├── Результат      (/meetings/result)
  ├── Новая встреча  (/meetings/new)
  └── Календарь      (/meetings/calendar)
```

Стиль: карточки и поля как в `CallWizard` / `content-card`.

## Доступ и «конфликты» (что имелось в виду)

**Чужие строки:** менеджер **видит** их, но **не может сохранить** — при попытке записи сервер отвечает отказом (403). В интерфейсе чужая встреча сразу в режиме просмотра.

**«Кто последний сохранил»** — про редкий случай, когда **одну и ту же свою** встречу меняют дважды:

- открыли на телефоне и на планшете;
- два вкладки браузера;
- сохранили старую версию после того, как коллега уже нет — **свою** строку перезаписали сами.

Google Таблица не блокирует строку при редактировании из приложения: **побеждает последнее нажатие «Сохранить»**. Для вашего сценария (каждый правит только свои встречи) это обычно не проблема; при желании позже можно добавить подсказку «данные на сервере новее».

## Риски

| Риск | Митигация |
|------|-----------|
| Лимиты Google Sheets API | Кэш календаря на 1–2 мин; batch read |
| Ошибка записи | Сообщение + не закрывать форму до успеха |
| Запись в чужую строку | Сервер: запись только если email строки = текущий пользователь |
| Двойное сохранение одной строки | Редко; последнее сохранение актуально |

## Что нужно от заказчика перед реализацией

1. Ссылка на таблицу + доступ service account (Редактор).
2. Список колонок: телефон, ID сделки, email менеджера, дата встречи, статус выполнения, поля формы.
3. Какие **три колонки** определяют «выполнено».
4. Образец заполненной строки.
