# Тест знаний (скрипт, JTBD, воронки) — план на будущее

> **Статус:** реализовано (меню «Тест», API, админ-вкладка «Тесты»).  
> **Триггер:** **«Давай к тесту»** / **«вернёмся к тесту»**.  
> **Файл:** `docs/test-plan.md`

## Итоговые требования (согласовано)

- Пункт меню **«Тест»**.
- **20 вопросов за попытку** — каждый раз **случайные 20 из банка ~200** (`data/test-questions.json`, генератор `scripts/generate-test-questions.mjs`).
- **Порог «сдал»:** ≥ **16 из 20** (80%) — показывать в итоге («Сдал» / «Не сдал») для прогресса.
- **20 вопросов** подряд (один на экран; ответ → следующий вопрос).
- Темы: **скрипт квал ОГЗ**, **JTBD**, **распределение лида по воронке**, **пороги бюджета** (S/M/L/XL), **модель продаж**, приоритеты, нецелевые сценарии и т.п.
- Формат: **варианты ответов** (один правильный, остальные неправильные).
- **Финал:** итог (балл / %), список **ошибок** — вопрос, выбранный ответ, **правильный ответ** (с кратким пояснением при желании).
- **Админ:** статистика — сколько тестов пройдено, **результаты по каждому пользователю** (email из авторизации).

## UX (черновик)

```
/menu → Тест (/test)
  → Старт («Начать тест»)
  → Вопрос 1/20 … 20/20 (прогресс-бар как в CallWizard)
  → Экран результата
```

- Повторное прохождение — **разрешено** (каждая попытка сохраняется отдельно).
- Во время теста — без подсказок и без возврата к прошлому вопросу (MVP); «Назад» — опционально позже.

## Источник правильных ответов

Вопросы не «от балды» у LLM, а из **продукта**:

| Тема | Откуда брать эталон |
|------|---------------------|
| Воронки CRM | `lib/scoring.ts` — `calculateFunnel`, `FUNNEL_LABELS` |
| Нецелевой А/Б/В | `calculateNonTargetResult`, `script-engine` |
| Бюджет S/M/L/XL | `budgetClassFromRub`, пороги в рублях |
| Потенциал 10/20/30 | скрипт, scoring |
| JTBD сегменты | `data/jtbd.json`, `SEGMENT_PHRASES` |
| Модель продаж | `lib/sales-model-content.ts` |
| Порядок шагов скрипта | `lib/script-engine.ts` |

Хранение вопросов: **`data/test-questions.json`** (или несколько файлов по темам) — правки без пересборки логики, версия набора `v1`.

Пример структуры вопроса:

```json
{
  "id": "funnel-focus-01",
  "topic": "воронка",
  "text": "…",
  "options": [
    { "id": "a", "label": "…", "correct": true },
    { "id": "b", "label": "…", "correct": false }
  ],
  "explanation": "…"
}
```

Для запуска: **случайные 20** из банка при каждой попытке (`randomize: true` в манифесте). Банк: **200 вопросов**, сгенерированы по скрипту/воронкам/JTBD/модели продаж.

Сгенерировать/обновить банк локально:

```cmd
импорт-тест-вопросы.cmd
```
или `npm run test-questions`

## Хранение попыток

Как статистика звонков (`lib/call-stats.ts`):

```typescript
type TestAttempt = {
  id: string;
  completed_at: string;
  user_email: string;
  score: number;           // например 17
  total: number;           // 20
  percent: number;
  wrong: Array<{
    question_id: string;
    question_text: string;
    chosen_label: string;
    correct_label: string;
    explanation?: string;
  }>;
};
```

Redis / `data/test-attempts.json` на dev.

## API (черновик)

| Метод | Кто | Назначение |
|-------|-----|------------|
| `GET /api/test/questions` | авторизованный | 20 вопросов **без** флага `correct` в ответе клиенту |
| `POST /api/test/submit` | авторизованный | массив `{ questionId, optionId }` → сервер считает балл, сохраняет попытку, возвращает разбор |
| `GET /api/admin/test/stats` | admin | сводка: по пользователям, число попыток, средний %, последняя дата |

**Важно:** правильные ответы проверяются **только на сервере** (не доверять клиенту).

## Админ-статистика

Расширение раздела **Администрирование** (вкладка «Тесты» рядом со «Статистика звонков»):

- таблица: email, число прохождений, последний результат, средний балл;
- фильтр по периоду (опционально v2);
- детализация по пользователю: список попыток с датой и %.

## Оценка сложности

| Часть | Сложность |
|-------|-----------|
| UI теста (как wizard) | Низкая |
| JSON вопросов + authoring 20 шт. | Средняя (контент от РОП) |
| API submit + storage | Низкая (паттерн как call-stats) |
| Админ-статистика | Низкая–средняя |

## Риски

| Риск | Митигация |
|------|-----------|
| Устаревшие вопросы после смены скрипта | Поле `version` в JSON; пересмотр вопросов при изменении scoring |
| Списание ответов в клиенте | Только server-side grading |
| Мало вопросов в банке | Старт с 20; потом расширение банка |

## Банк вопросов (готово к реализации)

- Файл: `data/test-questions.json` (создаётся командой выше).
- Типы и выборка 20: `lib/test-questions-types.ts`, `lib/test-questions-bank.ts`.
- Темы: script, jtbd, funnel, budget, non_target, priority, sales_model, general.

## Что нужно перед UI-реализацией

1. Запустить `импорт-тест-вопросы.cmd` и закоммитить JSON в git.
2. РОП может выборочно поправить формулировки в JSON.
3. При изменении скрипта/scoring — перегенерировать или обновить затронутые вопросы.
