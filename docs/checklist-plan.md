# ЧекЛист — план интеграции (черновик, не реализовано)

> Триггер для ассистента: когда пользователь пишет **«Давай вернемся к Чек листу»** — показать этот документ (кратко + ссылка на файл).

## Идея

Менеджеры на выезде заполняют Google Form. Нужно в приложении «Цифра»:

- пункт меню **«ЧекЛист»**;
- пошаговые **окна как в скрипте ОГЗ** (не вид Google Form);
- данные уходят в Google и **обновляются централизованно** онлайн.

## Почему не «просто встроить Google Form»

| Подход | Плюсы | Минусы |
|--------|--------|--------|
| iframe Google Form | Быстро, форма всегда актуальна | Выглядит как Google, не как приложение |
| Свой UI + POST в formResponse | Ответы в той же Form | Нужны entry.xxx ID; ветвления/файлы сложны; ломается при изменении формы |
| Официальный Forms API | — | Нет полноценного API для рендера формы в своём UI |

## Рекомендуемый путь (как Референс)

**Вариант A — Google Таблица (рекомендуется):**

1. Вкладка **«Схема чеклиста»** — вопросы, тип поля, обязательность, порядок, условия показа.
2. Вкладка **«Ответы»** — одна строка = один выезд.
3. Приложение читает схему через Service Account и рисует wizard (карточки, `btn-wizard`, прогресс).
4. Обновление формы = правка таблицы → менеджеры видят новую версию после обновления.

**Вариант B — свой UI + отправка в Google Form:**

- Подходит для **простого линейного** чеклиста.
- Нужно один раз снять `entry.123456789` для каждого поля.
- При изменении формы в Google — пересинхронизация ID.

## UX для менеджера

Тот же паттерн, что CallWizard:

- метка «ЧекЛист», прогресс-бар, карточка с вопросом;
- кнопки-ответы / поля ввода;
- «Назад» / «Далее»;
- финал: «Отправить» + «Новый выезд».

## Обновление «онлайн»

| Что меняется | Таблица-схема | Google Form |
|--------------|---------------|-------------|
| Текст вопроса | Правка ячейки | Маппинг / код |
| Новый вопрос | Новая строка | Новый entry.xxx |
| Ветвления | Колонки show_if | Сложно повторить 1:1 |

Заложить **версию схемы** (v1, v2…), чтобы не ломать черновики.

## Связь с платформой

- Меню → `/checklist` (или аналог);
- авторизация — только свои менеджеры, в ответ `user_email` + `manager_name`;
- позже — статистика в админке (как звонки);
- офлайн — черновик в localStorage, отправка при сети;
- фото с объекта — проще через свой UI + Drive, чем через Form URL.

## Этапы (когда начнём)

1. **MVP** — линейный чеклист, схема + ответы в таблице, UI как wizard.
2. **v2** — ветвления, обязательные поля, черновики.
3. **v3** — фото, геолокация, статистика в админке.
4. При необходимости — синхронизация с существующей Google Form.

## Вывод

**Да, можно:** свой wizard + Google (таблица или Form) как backend.  
**Лучше всего:** схема и ответы в **Google Таблице** — как уже сделано для Референса.

При старте реализации нужна ссылка на текущую Google Form или список полей — оценить вариант A vs B.
