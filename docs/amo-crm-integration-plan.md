# Интеграция amoCRM — план (не реализовано)

> Триггер: **«Давай к интеграции amo»** / **«вернёмся к amo»** — показать этот документ.

## Идея

На экране **итога скрипта «Скрипт квал ОГЗ»** — кнопка **«Выгрузить в CRM»**.

1. Сервер ищет сделку в amoCRM.
2. Найдена → создаёт **примечание** с текстом (как «Копировать для CRM»: воронка, приоритет, сегмент, телефон, ID, менеджер и т.д.).
3. Не найдена → понятная ошибка менеджеру.

## Правила поиска (обязательно)

### Если введён ID сделки

- Поиск **только по ID** (ID = ID лида/сделки в amoCRM).
- Не подставлять телефон вместо ID, если ID указан.
- Если по ID не найдено — сообщить об ошибке (или отдельно обсудить fallback на телефон; по умолчанию: **сначала ID, без подмены формата**).

### Если ID не введён (или пустой) — поиск по телефону

- Номер **нормализовать** перед запросом в amo:
  - только цифры;
  - формат **`79999999999`** (11 цифр, Россия: `7` + 10 цифр);
  - **без** `+`, **без** `-`, **без** пробелов и скобок.
- Примеры:
  - `+7 (999) 123-45-67` → `79991234567`
  - `89991234567` → `79991234567` (ведущая `8` → `7`)
  - `9991234567` → `79991234567` (добавить `7`, если 10 цифр)

### Порядок (как согласовано)

```
Есть dealId в анкете?
  да → поиск по ID в amo
  нет / пусто → нормализовать телефон → 79999999999 → поиск по телефону
```

При нескольких сделках на один телефон — выбор сделки или правило «последняя активная» (уточнить при старте).

## Технически (кратко)

- Кнопка в `CallWizard` на итоге (целевой + нецелевой).
- `POST /api/amo/export` — только сервер, токены amo в env (Vercel).
- amo API: поиск лида по ID, поиск контакта/лида по телефону, `POST .../leads/{id}/notes`.

## Нужно от заказчика при реализации

- Поддомен amo, OAuth/интеграция в amoМаркет.
- Подтверждение: `dealId` в скрипте = ID сделки в amo.
- Поведение: 0 сделок / несколько сделок по телефону.
- Дубликаты примечаний (разрешить повтор или блокировать).

## Этапы

1. **MVP** — нормализация телефона `799…`, поиск по ID если есть, иначе по телефону, одно примечание.
2. **v2** — выбор сделки при нескольких совпадениях, статус «уже выгружено».
